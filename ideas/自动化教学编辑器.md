# 自动化教学编辑器

## 产品想法

让学习者一次只执行一个编程任务。学习者完成代码后，不需要手动回复“完成”或复制运行结果；插件自动收集本地证据，由 AI 教师判断学习状态、提供分级提示并生成下一步。

## 要解决的问题

目前使用 AI 学习编程时，流程通常是：

1. AI 给出操作步骤。
2. 学习者在编辑器中修改代码。
3. 学习者手动告诉 AI“完成了”。
4. 学习者复制运行结果或报错给 AI。
5. AI 判断后再给出下一步。

这里有大量重复反馈。产品希望把第 3、4 步自动化。

## 核心闭环

```text
AI 生成一个教学任务
→ 学习者修改代码
→ 监听文件和运行状态
→ 本地执行编译、测试等确定性检查
→ AI 结合代码差异和本地证据判断
→ 成功后生成下一步
→ 失败时按等级提供提示
```

## 第一版 MVP

第一版不从零开发完整编辑器，优先制作 VS Code 插件。

只实现以下能力：

- 一次只展示一个任务。
- 监听文件创建和代码修改。
- 执行编译、测试或 HTTP 请求等验收规则。
- 调用 AI 教师判断学习状态并生成下一步。
- 代码通过后提出一个理解问题。
- 显示“进行中、检查中、已通过、需要修改”状态。
- 验收通过后自动进入下一任务。

AI 教师是产品核心，本地规则是向 AI 提供可信证据的辅助层。第一版只支持“前端转 Java 全栈”一条路线，不做通用编程代理。

## 本地证据示例

```json
{
  "instruction": "创建 ReportRequest record",
  "localChecks": [
    "ReportRequest.java 文件存在",
    "包含 stockCode、year、revenue 三个字段",
    "Maven 编译成功"
  ]
}
```

## 产品边界

- 默认教学模式只给分级提示，由学习者亲手完成。
- 代码可以运行不等于掌握，还需要学习者解释原因。
- 不在每次输入时调用 AI，只在保存、防抖和本地检查完成后调用。
- 默认只发送当前任务相关的代码差异和检查结果，不发送整个仓库。
- MVP 不提供 AI 自动修改代码模式。

## 真实需求收集

继续 Java 学习时，记录以下场景：

- 哪些步骤需要学习者回复“ok”。
- 哪些结果需要手动复制给 AI。
- 哪些任务可以通过文件、编译、测试或接口自动验证。
- 哪些任务无法可靠地自动判断。

积累 10～20 个真实场景后，再开始实现 MVP。
