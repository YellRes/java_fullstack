# 自动化教学编辑器

## 产品想法

让学习者一次只执行一个编程任务。学习者完成代码后，不需要手动回复“完成”或复制运行结果，编辑器会自动检查、验收并进入下一步。

## 要解决的问题

目前使用 AI 学习编程时，流程通常是：

1. AI 给出操作步骤。
2. 学习者在编辑器中修改代码。
3. 学习者手动告诉 AI“完成了”。
4. 学习者复制运行结果或报错给 AI。
5. AI 判断后再给出下一步。

这里有大量重复反馈。产品希望把第 3、4 步自动化。

## 核心闭环

```text
展示一个教学任务
→ 学习者修改代码
→ 监听文件和运行状态
→ 自动执行验收规则
→ 成功后进入下一步
→ 失败时只提示当前问题
```

## 第一版 MVP

第一版不从零开发完整编辑器，优先制作 VS Code 插件。

只实现以下能力：

- 一次只展示一个任务。
- 监听文件创建和代码修改。
- 执行编译、测试或 HTTP 请求等验收规则。
- 显示“进行中、检查中、已通过、需要修改”状态。
- 验收通过后自动进入下一任务。

第一版先使用固定课程和固定验收规则，不急着接入 AI。

## 验收规则示例

```json
{
  "instruction": "创建 ReportRequest record",
  "checks": [
    "ReportRequest.java 文件存在",
    "包含 stockCode、year、revenue 三个字段",
    "Maven 编译成功"
  ]
}
```

## 后续模式

- 教学模式：只给提示，由学习者亲手完成。
- 协助模式：失败后询问是否帮助修改。
- 自动模式：获得授权后直接修改并继续。

## 真实需求收集

继续 Java 学习时，记录以下场景：

- 哪些步骤需要学习者回复“ok”。
- 哪些结果需要手动复制给 AI。
- 哪些任务可以通过文件、编译、测试或接口自动验证。
- 哪些任务无法可靠地自动判断。

积累 10～20 个真实场景后，再开始实现 MVP。
