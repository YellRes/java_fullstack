### ⚠️ 今天两个必踩的坑，提前避掉

**坑 1：不要加 MySQL / JPA / Redis 依赖。**
加了它们，Spring Boot 检测到"有数据源依赖"却找不到连接配置 → **启动直接失败**。第一天最不该发生的事就是启动报错。数据库等阶段 1。

**坑 2：Controller 必须放在主类所在包或它的子包下。**
`@SpringBootApplication` 只扫描自己所在包及子包。放错地方 → 不报错、启动正常、访问 404，最难查。
主类在 `com.zhangtianrui.adboard`，Controller 就放 `com.zhangtianrui.adboard.controller`。

## ④ 写第一个 Controller ← 今天的正题

新建 `src/main/java/com/zhangtianrui/adboard/controller/PingController.java`：

```java
package com.zhangtianrui.adboard.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class PingController {

    @GetMapping("/api/ping")
    public /* TODO: 返回什么类型？ */ ping() {
        // TODO: 你来决定返回什么形状的 JSON
    }
}
```

**为什么这 5 行要自己写**：这个返回值的形状就是整个项目「统一响应体」的雏形，阶段 1 会把它抽成 `Result<T>`，之后所有接口都长这样。而决定它该长什么样，**恰好是你比后端新人强的地方**——你在前端被烂接口坑过。

需要权衡的选项：

| 写法 | 代价 |
|---|---|
| `return "pong";` | 最简单，但返回纯文本不是 JSON。以后加字段要改类型 |
| `return Map.of("msg", "pong");` | 是 JSON 了，但 Map 没类型约束，字段名写错编译器不管（想想没有 TS 的日子） |
| 定义一个 `record` 当返回类型 | 有类型、字段明确、能补全，但要多写一个类 |
| 现在就上 `code`/`message`/`data` 包装？ | HTTP 已有状态码，再包一层是冗余还是必要？你在前端处理错误时更希望后端怎么给？ |

选哪个都能跑通。**关键是选完能说出理由。**

写完重启（`Ctrl+C` 再 `./mvnw spring-boot:run`），访问 `localhost:8080/api/ping`。
