## ① 版本决策：Boot 4.1.0 要不要降到 3.x（10 min）

现在的 `pom.xml`：Spring Boot **4.1.0**，依赖名 `spring-boot-starter-webmvc`。

**问题**：教程/StackOverflow/掘金 99% 写的是 `spring-boot-starter-web`（Boot 3.x 及以前）。Boot 4 拆成了 `webmvc` / `webflux`。你复制任何教程的 pom 片段都会对不上。

**怎么决定**：打开 start.spring.io，把 Spring Boot 下拉框切到 **3.x 最新的稳定版**，点 Explore 看它生成的 `pom.xml`——照抄版本号和 starter 名字（不用我给版本号，去看权威来源）。

| | 留在 4.1.0 | 降到 3.5.x |
|---|---|---|
| 资料密度 | 低，遇到问题搜不到答案 | 海量 |
| 国内生态（MyBatis-Plus 等） | 适配程度未知，**阶段 1 才会知道** | 成熟无缝 |
| 技术新度 | 更新 | 落后一个大版本 |
| 现在切换的成本 | — | **几乎为零**（只有一个 Controller） |

**我的建议：降到 3.x。** 理由不是 4.1 不好，是你每天只有 1 小时，不该把时间花在"全网只有 3 个帖子讨论过我这个问题"上。同 Java 选 21 不选最新的逻辑。

### (b) "学到的概念"再深一层

昨天写的是：

> GetMapping 把 http 中所有 api/ping 路径的请求打到了 ping() 方法中处理

对，但停在"是什么"。缺的是「**谁**把请求打过去的」。

**关键事实：Java 里的注解本身不做任何事，它只是一段元数据，等同于一张贴纸。** `@GetMapping` 自己没有能力路由请求。所以必然有个东西在读这张贴纸。

带着这三个问题重答：

1. 谁在读这些注解？**在什么时候**读（启动时？每次请求时？）
2. 读完之后存到哪去了？（提示：和前端 `router.get()` 塞进的那张表，本质是不是同一个东西？）
3. 如果 Controller 放在主类包**外面**，上面这个过程哪一步会断掉？—— 这就是你昨天避开的坑 2 的原理

想清楚这三个，你会同时白拿：为什么将来 `@Transactional` 会莫名失效（同一个机制）、以及声明式框架的根本代价（控制流不可见，出问题不知道去哪找）。

## ③ 今天的正题：POST 接口（27 min）

主线项目是广告数据看板，所以不写 hello world，直接写第一个真实的业务接口。

**目标**：

```
POST /api/campaigns
Content-Type: application/json

{ "name": "夏季promo", "budget": 5000, "enabled": true }
```

返回：把收到的数据回显 + 一个生成的 id（还没数据库，id 先用 `System.currentTimeMillis()` 或随便一个数字顶着）。

新建 `src/main/java/com/yellres/demo/controller/CampaignController.java`：

```java
package com.yellres.demo.controller;

import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class CampaignController {

    @PostMapping("/api/campaigns")
    public /* TODO: 返回什么类型？ */ create(@RequestBody /* TODO: 用什么类型接收？ */ req) {
        // TODO
    }
}
```

### 注意这个 body 是故意设计的

三个字段是**三种不同类型**：`String` / 数字 / 布尔。所以：

- 用 `Map<String, String>` 接收 → **接不了**，budget 和 enabled 不是字符串
- 改成 `Map<String, Object>` → 能接，但每次用都要强转 `(Integer) req.get("budget")`，类型信息全丢，且写错字段名编译器不管
- 定义一个 `record` → 字段名和类型都是编译期约束的

这就是昨天那张表里 `Map` 的第二个代价，今天亲手撞一次。

**建议的做法**：先用 `Map<String, Object>` 跑通一次，**亲自感受强转和字段名硬编码的难受**，再改成 `record`。别跳过第一步——跳过了就只是听我说 record 更好，做过了才是自己的判断。

Java 21 的 record 长这样（一行就是一个不可变数据类，自动有构造器/getter/equals/toString）：

```java
public record CampaignRequest(String name, Integer budget, Boolean enabled) {}
```

放哪：新建 `dto` 包，`com.yellres.demo.dto.CampaignRequest`。
**为什么单独建包**：这是阶段 1「Entity / DTO / VO 分三套」的起点。现在只有 1 个类，先把位置放对，将来不用搬。

### 顺手会遇到的一个认知差异

前端 `JSON.parse()` 出来就是可用对象，因为 JS 对象和 JSON 本来同构。

Java 里 JSON → 对象叫**反序列化**（Jackson 干的），它需要知道目标类型、需要字段名匹配规则。这是静态类型的代价。

**留一个问题**（不用今天解决，但记住它）：如果前端传的是 `{"is_enabled": true}`（下划线），你的 record 字段叫 `enabled`，会发生什么？——这是全栈最经典的一类联调 bug，将来你两端都要负责，会庆幸自己早知道。

## ④ 用 `.http` 文件测试（10 min）

POST 没法用浏览器地址栏测。装 VS Code 扩展 **REST Client**（发布者 `humao`），然后在项目根目录建 `api.http`：

```http
### 健康检查
GET http://localhost:8080/api/ping

### 创建 campaign
POST http://localhost:8080/api/campaigns
Content-Type: application/json

{
  "name": "夏季promo",
  "budget": 5000,
  "enabled": true
}
```

每个 `###` 上方会出现 `Send Request`，点一下就发。

**为什么用 `.http` 而不是 Postman**：

1. 这个文件**能提交进 git**，成为项目文档的一部分——新人（包括三个月后的你）clone 下来就知道有哪些接口、怎么调。Postman 的 collection 在云端，不在代码库里。
2. **IDEA Ultimate 内置支持同样的 `.http` 格式**。第 3 周切 IDEA 时这个文件直接能用，零迁移成本。

顺手试一件事：把 body 里的 `"budget": 5000` 改成 `"budget": "abc"` 再发，看后端返回什么。**这是你第一次见到 Spring 的默认错误响应**——记住它有多难看，阶段 1 的「全局异常处理」就是为了修它。
