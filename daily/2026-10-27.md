## 复习笔记

### class / interface / record

| | 是什么 | 能不能 new |
|---|---|---|
| interface | 约定"能做哪些事"，方法只有签名、以分号结尾 | 不能 |
| class | 真正干活，必须实现它 `implements` 的接口里的全部方法，少一个编译不过 | 能 |
| record | 专门装数据的简写 class，字段不能改，自动生成构造方法、取值方法、equals、toString | 能 |

- 和 TS 不同：TS 的 interface 描述数据长什么样，编译后删掉；Java 的 interface 描述能做的事，运行时还在，必须显式写 `implements`
- 定义接口的意义：Service 只依赖接口，内存版换成 MySQL 版时 Service 不用动；测试时也能换成内存版

### 继承 extends

- 搭配：`class extends class`（只能一个）、`class implements interface`（可以多个）、`interface extends interface`
- extends 拿到父类现成的代码，是"我是一种 XX"；implements 只拿到约定，是"我能做 XX"
- 没写 extends 默认继承 `Object`；`final` 的类不能被继承（record、String 都是）
- 业务代码里少用继承，多用接口 + 组合；会写的继承主要是自定义异常（`extends RuntimeException`）和 MyBatis-Plus 的 `BaseMapper`

### 和 JS 原型链对比

- 相同：方法都是"自己没有就往上找"，一直找到 Object
- 不同：JS 是对象和对象之间的关系，运行时能改（往 prototype 上挂方法）；Java 是类和类之间的关系，编译时就定死，运行时改不了
- 所以 Java 没法给 String 加方法（Object 在 JDK 里，String 又是 final），通用功能写成工具类的静态方法：`StringUtils.shout(s)`
- `static` 方法属于类本身，不用 new，用"类名.方法名"调用，相当于前端 `utils/` 里的函数

### Map

- `new HashMap<>()` 单线程用；`new ConcurrentHashMap<>()` 多线程安全，**不能存 null**；`Map.of(...)` 只读，也不能有 null
- 常用：`put` / `get`（找不到返回 null）/ `getOrDefault` / `containsKey` / `remove` / `size()`
- `forEach((key, value) -> ...)`，参数顺序和 JS 的 `(value, key)` 相反
- 左边写接口 `Map`、右边 new 具体实现，和 Service 依赖 Repository 接口是同一个套路

### Optional

- `Optional.of(x)`：x 一定不是 null，是 null 直接报错
- `Optional.ofNullable(x)`：x 可能是 null，是 null 就得到空盒子
- `Optional.empty()`：直接造一个空盒子
- 空盒子也是真实的对象（全局就一个），可以放心调 `isPresent()`、`orElseThrow()`；返回 null 的话一调方法就空指针

### 基本类型和包装类

| 基本类型 | 包装类 |
|---|---|
| byte / short / **int** / **long** | Byte / Short / **Integer** / Long |
| float / **double** | Float / Double |
| **boolean** / char | Boolean / **Character** |

- 首字母大写就是包装类，例外是 `int → Integer`、`char → Character`；String 不是基本类型
- 整数默认是 int，`1L` 才是 long；小数默认是 double，`0.1f` 才是 float
- 基本类型不能是 null（默认 0），包装类可以。DTO 和实体一律用包装类：`Long id` 没生成时是 null，`long id` 是 0，分不清"没有"和"就是 0"
- 坑 1：包装类是 null 时自动拆箱成基本类型会空指针
- 坑 2：包装类比较用 `equals`，不要用 `==`。-128～127 有缓存，`==` 恰好成立；超出范围就不成立了（id 一大就出 bug）

### 数字精度

- `double` 和 JS 的 number 一样：`0.1 + 0.2 == 0.3` 是 false
- 整数精确，但溢出不报错，会变成负数：`Integer.MAX_VALUE + 1` 是 -2147483648。播放量这种可能很大的数用 `Long`
- 要精确（金额）用 `BigDecimal`，并且从字符串创建：`new BigDecimal("0.1")`
- 小数默认用 double；float 只在海量数据、对精度不敏感时用（W19 的向量）
