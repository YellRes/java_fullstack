## 主线项目：BiliScout

**输入一个问题（例：“什么枕头适合侧睡”）→ 搜 B 站视频 → 读字幕和评论 → 去掉恰饭 → AI 总结成一份带出处的情报报告**。单个 Java 服务负责采集/存储/AI 流水线/对外 API，Vue3 做页面，只在本地跑。

📋 **26 周执行计划：[PLAN.html](PLAN.html)**（双击打开，含可勾选的周进度追踪）
📐 **完整设计：[docs/design-2026-10-21-biliscout.html](docs/design-2026-10-21-biliscout.html)**（目标与边界、报告样例、判恰饭的线索）

已定决策：

| 项 | 决定 | 理由 |
|---|---|---|
| 数据来源 | 只做 B 站 | 有字幕和评论接口，签名算法社区已公开；抖音、小红书要逆向防护，不碰 |
| 部署 | 只在本地跑 | 只有自己能发起查询，B 站小号和 AI 费用不会被别人刷 |
| 服务架构 | 单个 Java 服务 | B 站接口 Java 直接调够用，去掉 Python 采集服务，省下的时间花在 Java 上 |
| AI 模型 | DeepSeek API | 便宜、中文好、OpenAI 兼容接口。负责改写关键词、判恰饭、提观点、汇总、追问 |
| 报告 | 每条结论带原视频 + 时间点；恰饭列出并写理由 | 能核实，广告判断不是黑箱 |
| 没字幕的视频 | 跳过并计数 | 下载音频转文字复杂度高，对练 Java 没帮助 |
| 向量存储 | MySQL 主库 + PostgreSQL(pgvector) 只存向量 | 面试问的基本是 MySQL，主库不换；追问功能才需要向量（W19） |

三条必守的红线：

1. **自用、低频、用小号** —— 这是违反 B 站用户协议的自动化访问。请求间隔 1–3 秒，被拦（412）就停，不对外分发采集到的内容，报告只放摘要和链接。
2. **只用公开的 WBI 签名，不逆向任何平台的防护** —— 不碰小红书、抖音的签名。
3. **密钥和登录信息绝不进 git** —— DeepSeek Key、向量接口 Key、B 站小号的 `SESSDATA` 都用环境变量或 gitignore 掉的本地配置文件。GitHub 有密钥扫描，泄露的 key 几分钟就会被用掉。

> 每天动完手，回来改这张表（连续天数 + 累计投入 + 下一个动作）。
> 「下一个动作」这一格是**最重要的**——它让你第二天坐下来就能开始，不用花 10 分钟想"今天干什么"。1 小时/天的预算里，10 分钟是 1/6。

## 三条不能忘的纪律

1. **每次都动手。** 不要"周一读理论周二写代码"。1 小时 = 5 分钟回顾 + 50 分钟写 + 5 分钟记日志。
2. **卡住超 20 分钟就问 AI，但要解释不要代码。** 直接拿代码会让你半年后仍然只会抄。同时把这个坑记进 `troubles/`。
3. **宁可慢不要断。** 加班那天做 10 分钟也算。断三天以上要重新热身，成本极高。

## 两条已定的取舍（别中途推翻）

- **先不学**：Spring Cloud 全家桶、Kafka 深入、Spring Security、JVM 调优参数、分布式事务。理由：1h/天下只能产出"会配置不懂原理"的假技能，面试一追问就穿。
- **定位是「能吃下整条链路的前端」**，不是「Java 后端候选人」。预算不支持后者，而前者的竞争对手更弱、你的前端经验是资产而非包袱。
