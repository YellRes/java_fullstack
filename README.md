## 主线项目：StockAI

**A 股财报采集 → 指标计算 → AI 解读**。双服务架构：Python 负责采集清洗，Java 负责存储/业务/AI/对外 API，Vue3 做看板。

📋 **完整设计 + 24 周执行计划：[PLAN.html](PLAN.html)**（双击打开，含可勾选的周进度追踪）

已定决策：

| 项 | 决定 | 理由 |
|---|---|---|
| AI 模型 | DeepSeek API | 便宜（全项目预计 < 50 元）、中文财报理解好、OpenAI 兼容接口 |
| 数据采集 | 独立 Python 服务 | Python 采集生态强（akshare）。**时间上限 2 周，之后不再投入** |
| 服务间通信 | Python 调 Java 的批量上报接口 | Java 保持唯一写入口，正好练批量插入/幂等/事务边界 |
| MVP 范围 | 只做财报解读 | 不做自选股/回测。8 个核心指标，不碰完整三表 |
| 财报表设计 | 宽表（非 EAV 窄表） | 指标集合稳定，"加指标不改表"这个优点用不上，而窄表的 SQL 复杂度和 50 倍行数天天要付 |

三条必守的红线：

1. **AI 只输出财务特征和风险点，不输出买入/卖出建议** —— 面向公众提供投资建议在国内是持牌业务。加免责声明。
2. **爬虫要有节制** —— 请求间隔 1–3 秒、看 robots.txt、只采公开数据、不做商业化分发。
3. **DeepSeek API Key 绝不进 git** —— 用环境变量或 gitignore 掉的本地配置文件。GitHub 有密钥扫描，泄露的 key 几分钟就会被用掉。

> 每天动完手，回来改这张表（连续天数 + 累计投入 + 下一个动作）。
> 「下一个动作」这一格是**最重要的**——它让你第二天坐下来就能开始，不用花 10 分钟想"今天干什么"。1 小时/天的预算里，10 分钟是 1/6。

## 三条不能忘的纪律

1. **每次都动手。** 不要"周一读理论周二写代码"。1 小时 = 5 分钟回顾 + 50 分钟写 + 5 分钟记日志。
2. **卡住超 20 分钟就问 AI，但要解释不要代码。** 直接拿代码会让你半年后仍然只会抄。同时把这个坑记进 `troubles/`。
3. **宁可慢不要断。** 加班那天做 10 分钟也算。断三天以上要重新热身，成本极高。

## 两条已定的取舍（别中途推翻）

- **先不学**：Spring Cloud 全家桶、Kafka 深入、Spring Security、JVM 调优参数、分布式事务。理由：1h/天下只能产出"会配置不懂原理"的假技能，面试一追问就穿。
- **定位是「能吃下整条链路的前端」**，不是「Java 后端候选人」。预算不支持后者，而前者的竞争对手更弱、你的前端经验是资产而非包袱。
