# 踩坑记录

**每次卡超过 20 分钟，写一篇。** 文件名 `YYYY-MM-DD-短描述.md`。

## 为什么这个目录比 notes 更值钱

因为它是**面试素材的原料**。

"我知道索引是 B+ 树" —— 一眼是背的。
"我这个报表接口 8 秒，`EXPLAIN` 看到 type=ALL 全表扫，加了 (tenant_id, stat_date) 联合索引后 type 变 ref，P95 降到 80ms" —— 可以被追问三层。

后者只能从真实踩坑里长出来，而**踩坑的细节会在两周内忘干净**。所以要当场记。

面试时被问"你遇到过什么难题"，答案就从这个目录里挑。

## 模板

```markdown
# YYYY-MM-DD · 一句话标题

## 现象
（我看到了什么。贴真实报错/日志/耗时数字，不要转述）

## 我以为的原因（错的那个）
（记下来。错误的假设本身有价值——它暴露了我的认知盲区在哪）

## 真实原因
（为什么会这样。要到机制层，不能停在"改了就好了"）

## 怎么修的
（贴关键代码 diff）

## 前端有没有对应的坑
（有就写，这是我的记忆锚点；没有就写"前端不会遇到，因为……"）

## 面试怎么讲（30 秒版）
（提前写好。真到面试时临场组织语言必然磕巴）
```
