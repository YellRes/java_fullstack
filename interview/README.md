## 四、必答题（提前写好逐字稿，别临场组织）

### 1. 为什么不拆微服务？

> 我判断这个系统当前量级不需要拆分，单体 + 模块化更合适。如果 QPS 到 X、团队到 Y 人，我会先拆出报表服务——因为它的读写特征和主业务完全不同（读多写少、可容忍秒级延迟、查询重）。

这句话比"熟悉 Spring Cloud"值钱，因为它展示的是**工程判断力**，而判断力没法靠背书伪造。

### 2. 为什么从前端转过来？

答"想端到端负责结果"，**别答"前端不好找工作"**。后者会让面试官怀疑你的动机和稳定性。

### 4. 前后端边界怎么判断？（**这是我的差异化考点**）

判断框架（背下来，现场可套）：

- **数据量**大 → 靠数据源侧做（能吃索引）
- **安全性**相关 → 后端是唯一边界，前端只是体验
- **耗时**不可控 → 异步化 + 状态查询
- **纯展示交互** → 前端，别为它加一次往返
- **一致性**要求高（钱、库存）→ 后端事务，前端只做乐观提示

关键是**要主动说出反例**——"但纯 UI 的字段联动我会放前端"。展示"我知道边界在哪、也知道边界的另一侧"，这才是全栈的核心竞争力。
